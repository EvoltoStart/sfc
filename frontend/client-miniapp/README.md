# 微信小程序客户端说明

本目录是独立于后端代码的微信小程序客户端工程，位置为 `frontend/client-miniapp`，不会和 Go 后端代码混在一起。

## 技术形态

- 原生微信小程序
- JavaScript + WXML + WXSS
- 主包 + 分包结构
- 小程序接口默认指向 `http://127.0.0.1:18082`
- 小程序接口 fallback 指向 `http://127.0.0.1:8080`
- 开发态支付回调代理默认指向 `http://127.0.0.1:4174`

## 本地联调端口

- 后端 API：`http://127.0.0.1:8080`
- 客户端 Web 与小程序支付代理：`http://127.0.0.1:4174`
- 后台管理 Web：`http://127.0.0.1:5174`
- 小程序默认 API：`http://127.0.0.1:18082`，如果该端口不可用，会 fallback 到 `http://127.0.0.1:8080`

如果只跑后端和小程序，可确保 `8080` 后端可用；如果要测试小程序支付页里的“模拟支付成功”，需要同时启动客户端 Web 的 `4174` 代理。

## 微信开发者工具导入

1. 打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择 `D:\GoLang\workspace\sfc\frontend\client-miniapp`。
4. 使用已有 AppID 或测试号导入。
5. 在“详情 -> 本地设置”中关闭“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。
6. 确认本机后端和支付代理已经启动：
   - 后端 API：`8080` 或小程序默认端口 `18082`
   - 本地支付模拟代理：`4174`

## 推荐联调账号

- 乘客：`passenger-mini-fullchain`
- 车主：`driver-mini-fullchain`

这些账号名只是 fake 登录 code，后端会按 code 自动创建或复用用户。你也可以换成任意字符串，但同一轮乘客和车主请使用不同 code。

## 手动验收清单

乘客链路：

1. 使用乘客 code 登录，确认首页能加载路线预设。
2. 在首页选择“北京朝阳 -> 天津和平”或相近路线，点击搜索匹配。
3. 进入匹配列表和行程详情，确认司机、价格、顺路度、座位等信息可见。
4. 提交同行申请，进入订单中心确认申请状态。
5. 在车主接受后进入订单详情，创建支付单。
6. 在支付确认页点击“模拟支付成功”，确认通过 `4174` 代理触发后端回调并回查支付状态。
7. 进入安全中心，新增紧急联系人，保存安全配置，生成分享链接，上报 SOS，上传轨迹并查看轨迹摘要。
8. 支付成功后执行确认上车、确认到达，确认订单进入完成态。

车主链路：

1. 使用车主 code 登录。
2. 进入驾驶证认证页提交驾驶证，确认认证状态通过。
3. 进入车辆管理页新增车辆，确认车辆可用于发布。
4. 进入发布页，完成价格预览、顺路度校验和行程发布。
5. 在订单/申请列表中查看乘客同行申请并接受。
6. 订单完成后进入钱包页，确认余额和流水产生结算记录。

后台核查：

1. 登录后台管理系统 `http://127.0.0.1:5174`，账号为 `admin / admin123`。
2. 检查工作台、订单中心、安全与风控、财务中心、用户管理、操作审计页面能看到小程序联调产生的数据。

## 本地校验

在项目根目录执行：

```bash
node frontend/client-miniapp/scripts/verify-miniapp.js
```

校验内容包括：

- `app.json` 路由引用的页面是否存在
- 每个页面是否具备 `js/json/wxml/wxss`
- 每个页面引用的组件是否存在
- 全部 JSON 文件是否合法

## 注意事项

- 微信小程序访问本地 `http://127.0.0.1:18082` 主要用于开发者工具联调，真机调试时需要换成局域网地址或正式域名。
- 支付页里的“模拟支付成功”不会伪造前端状态，而是通过 `4174` 代理向真实后端回调，再回查真实订单与支付状态。
- 当前全链路本地联调使用 fake 微信登录、mock 支付回调和本地/沙箱能力，不代表真实生产支付能力已经完成。
- 优惠券、真实微信支付、MySQL Store、后台异步导出、监控部署仍在生产化阶段，不属于当前本地核心闭环范围。
