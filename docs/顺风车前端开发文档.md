# 顺风车前端开发文档

## 1. 文档目标

本文档用于指导顺风车项目的前端开发落地，面向以下对象：

1. 小程序前端开发
2. 管理后台前端开发
3. UI 设计与前端联调人员
4. Mock 数据与联调测试人员

本文档只关注前端开发，不展开后端实现细节。目标是让前端团队拿到文档后可以直接开始拆页面、建骨架、联接口。

## 2. 前端范围定义

### 2.1 前端产品形态

本项目包含两个前端：

1. 微信小程序
2. 管理后台 Web

### 2.2 小程序角色承载方式

小程序统一承载两种角色，不拆成两个小程序：

1. 乘客

## 3. 前端技术选型

### 3.1 小程序技术栈

1. 原生微信小程序
2. TypeScript
3. TDesign Mini Program
4. 自定义请求层
5. 小程序分包
6. 腾讯地图或高德地图小程序 SDK

### 3.2 后台技术栈

1. Vue 3
2. TypeScript
3. Vite
4. Element Plus
5. Pinia
6. Vue Router
7. Axios
8. ECharts

### 3.3 不建议的做法

1. 不建议小程序首页一次性加载全部地图能力和全部业务数据
2. 不建议把顺路度、价格、频控等规则写在前端
3. 不建议页面自行定义状态值，必须以统一枚举为准
4. 不建议每个页面单独维护一套请求封装和错误提示

## 4. 前端开发原则

### 4.1 页面开发原则

1. 每个页面必须有明确主操作
2. 每个页面必须覆盖关键状态，而不是只做单一静态图
3. 页面文案、状态、按钮权限必须来自统一常量定义
4. 地图只做辅助展示，不取代核心信息卡片
5. 所有费用展示必须使用后端返回结果

### 4.2 状态设计原则

1. 列表页负责浏览和筛选
2. 详情页负责状态判断和动作执行
3. 表单页负责输入与预校验
4. 涉及支付、确认、取消、审核的页面必须支持 loading、成功、失败三态

### 4.3 接口使用原则

1. 统一使用 `services/` 层调用 API
2. 页面层不直接拼 URL
3. 请求错误统一在请求层和页面层双层处理
4. 接口返回的枚举值必须先走 formatter 再展示
5. 所有写操作都要考虑重复点击防抖与幂等提示

## 10. 前端状态管理设计

### 10.1 小程序 store 划分

1. `userStore`：用户资料、认证信息、角色信息
2. `roleStore`：当前身份、角色切换能力
3. `orderStore`：当前查看中的订单摘要
4. `appStore`：城市、定位、全局开关

### 10.2 后台 store 划分

1. `appStore`：布局、主题、菜单
2. `userStore`：当前登录人信息
3. `permissionStore`：路由权限与按钮权限

### 10.3 不应放入全局状态的数据

1. 列表筛选参数
2. 页面局部弹窗开关
3. 一次性表单输入
4. 仅当前页面需要的 loading

## 11. 前端接口契约要求

### 11.1 返回结构统一

建议统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "trace-id"
}
```

### 11.2 状态字段要求

所有状态字段必须同时满足：

1. 返回枚举值
2. 返回展示文案或由前端统一映射
3. 支持颜色标签映射

示例：

```json
{
  "orderStatus": "PENDING_DEPART",
  "orderStatusText": "待上车"
}
```

### 11.3 金额字段要求

金额字段统一要求：

1. 后端返回最小货币单位或 decimal 字符串
2. 前端统一格式化为元
3. 不允许页面手工计算合计金额

### 11.4 时间字段要求

1. 统一使用 ISO 时间字符串或毫秒时间戳
2. 前端统一由 formatter 格式化
3. 相对时间展示只能用于辅助说明

## 13. UI 与前端协作要求

### 13.1 UI 交付要求

UI 交付给前端时必须包含：

1. 页面完整状态稿
2. 组件尺寸与间距规则
3. 字体与颜色规范

5. 空状态、错误状态、加载状态

### 13.2 前端切图要求

1. 优先使用组件化布局，不直接照图片硬编码
2. 能用文字与样式实现的，不导出位图

## 14. Mock 与联调要求

### 14.1 Mock 阶段

前端在后端未完成前，必须先完成：

1. 接口 TS 类型定义
2. Mock 数据结构
3. 状态枚举常量
4. 页面空状态和异常状态联调

### 14.2 联调阶段

重点联调链路：

1. 发布行程到完成订单
2. 乘客取消订单与退款
3. 频控拦截
4. 顺路度不通过拦截
5. SOS 上报
6. 轨迹展示与刷新

## 17. 最终建议

前端开发不要按“页面截图”推进，而要按“业务链路 + 状态组件 + 接口契约”推进。真正影响项目进度的不是页面多少，而是以下三件事是否统一：

1. 枚举和状态是否统一
2. 公共组件是否统一
3. 接口字段与异常处理是否统一

前端只要先把这三个基础打稳，后续页面扩展和联调成本会明显下降。
