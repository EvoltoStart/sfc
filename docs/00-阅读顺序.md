## 5. 真正开工时的使用方式

### 前端

先看：

1. 页面范围和组件规范
2. 对应接口
3. 自己负责的 Agent 边界

### 后端

先看：

1. 模块职责
2. 表结构
3. 接口清单
4. 事务与异步任务

### 项目负责人

先看：

1. Agent 任务单
2. 开发部署流程
3. 接口和表结构是否已经冻结

## 6. 文档维护顺序

后续如果发生变更，推荐按这个顺序更新：

1. 后端任务进度先改 `backend-task-docs/`
2. 接口变更再改 `顺风车OpenAPI接口清单.md`
3. 表结构变更再改 `顺风车MySQL表结构文档.md`
4. 业务说明变更再改 `顺风车前端开发文档.md` 或 `顺风车后端开发文档.md`
5. 最后改 `顺风车Agent开发任务单.md` 和 `顺风车全流程开发部署文档.md`

原因：

1. 后端任务文档记录执行状态，避免开发进度和文档脱节
2. 接口和表结构是团队共同基线
3. 业务文档应依赖接口和表结构，不应反过来驱动
