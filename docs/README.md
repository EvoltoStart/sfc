3. `顺风车全流程开发部署文档.md`

## 2. 文档职责说明

### `00-阅读顺序.md`

用途：

1. 告诉团队先看什么、后看什么
2. 区分项目负责人、前端、后端、测试、部署人员的阅读路径

### `顺风车前端开发文档.md`

用途：

1. 定义小程序和后台前端范围
2. 定义页面清单、分包、组件、状态管理、接口接入方式
3. 作为前端开发主文档

### `顺风车后端开发文档.md`

用途：

1. 定义后端模块边界
2. 定义状态机、规则、事务、异步任务和第三方集成
3. 作为后端开发主文档

### `顺风车全流程开发部署文档.md`

用途：

1. 定义环境、联调、测试、上线、回滚、监控流程
2. 作为项目推进和部署主文档

### `顺风车OpenAPI接口清单.md`

用途：

1. 定义前后端接口契约
2. 作为联调与接口评审基线

### `顺风车MySQL表结构文档.md`

用途：

1. 定义核心表、字段、索引、关系、建表顺序
2. 作为数据库与 migration 设计基线

### `顺风车Agent开发任务单.md`

用途：

1. 定义多 Agent 并行开发的边界
2. 约束责任域、依赖关系、交付物和验收标准

### `backend-task-docs/`

用途：

1. 记录后端全量审计结果
2. 提取尚未实现或尚未生产化闭环的存量功能
3. 按原子任务维护 `Done`、`Todo`、`Next`
4. 作为后续后端开发推进的任务事实源

## 4. 当前文档管理规则

为了避免再次出现多口径和重复方案，后续文档维护统一遵守以下规则：

1. 新增开发规则时，优先更新现有主文档，不新增同类文档
2. 接口变更优先更新 `顺风车OpenAPI接口清单.md`
3. 表结构变更优先更新 `顺风车MySQL表结构文档.md`
4. 任务边界变更优先更新 `顺风车Agent开发任务单.md`
5. 部署和上线流程变更优先更新 `顺风车全流程开发部署文档.md`
